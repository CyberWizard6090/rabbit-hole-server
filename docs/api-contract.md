# Контракт API и типы для клиента

Источник правды: [`openapi.yaml`](openapi.yaml). Из него и проверяются ответы сервера, и генерируются типы фронтенда.

## Как это устроено

1. **Схемы ответов.** У каждой операции успешный ответ ссылается на `components/responses/<Имя>` с типизированным `data`
   (и `pagination` для страничных списков). Общего ответа «что угодно» нет. Поля, которые сервер отдаёт всегда, перечислены в
   `required`; необязательные (`omitempty`) нет. Массивы и `tags`/`assignees` никогда не бывают `null`.
2. **Проверка на живых ответах.** Обёртка `contractHandler` (`tests/integration/contract_test.go`) стоит перед маршрутизатором
   каждого интеграционного теста и сверяет каждый JSON-ответ со схемой операции (kin-openapi). Расхождение роняет тест, в
   котором оно произошло, с путём к полю и телом ответа. Отдельных тестов на ответы писать не нужно: достаточно, чтобы любой
   тест вызвал маршрут.
3. **Что проверяют структурные тесты.** Каждая операция описывает `data` (кроме файлов, картинок и WebSocket, они перечислены
   в `responsesWithoutJSON` с причиной); файл `openapi.yaml` валиден и без повторяющихся ключей.
4. **Типы для клиента.** `go run ./cmd/apitypes` (или `make api-types`) пишет `docs/api-types.ts`: интерфейс на каждую схему и
   `Endpoints` с ключом `"МЕТОД /путь"`, где `params`, `query`, `body`, `status`, `data` и `pagination`. Тест
   `internal/apitypes` падает, если закоммиченный файл отличается от сгенерированного.

## Если вы меняете API

```bash
# 1. поправьте docs/openapi.yaml (схема и ссылка на ответ)
# 2. обновите типы
make api-types
# 3. прогоните интеграционные тесты: любое расхождение ответа со схемой упадёт
```

Образец использования на клиенте:

```ts
import type { Endpoints } from "./api-types";

type Ep = Endpoints["GET /tasks/{task_id}"];
async function getTask(id: number): Promise<Ep["data"]> { /* fetch, взять поле data */ }
```

Чтобы написать схему ответа по фактам, прогоните набор с `CONTRACT_SAMPLES=/tmp/samples.txt`: по одному настоящему ответу на
операцию и статус будет записано в файл.

## Ограничения

- Проверяются только успешные ответы и те ошибки, которые попали в `components/responses/Error`; формат ошибки одинаков
  (`code`, `params`, `details`, `request_id`).
- Поля внутри `json.RawMessage` (`Activity.old_value`, `AuditEntry.changes`, конфигурации шаблонов и форм) описаны как
  произвольные объекты: их форма зависит от типа события.
- Realtime-события WebSocket (`docs/realtime.md`) схемами пока не покрыты.
