# Формы, шаблоны и пользовательские поля

Полные схемы запросов и ответов: [`openapi.yaml`](openapi.yaml). Права: `form.read`, `form.manage`,
`template.read`, `template.manage`, `customfield.manage` ([`permissions.md`](permissions.md)).

## Жизненный цикл формы

```
draft  --publish-->  published  --archive-->  archived
```

- В черновике вопросы можно менять свободно.
- `POST .../publish` создаёт неизменяемую версию (`form_versions`). Публичная страница и отправки используют
  опубликованную версию; правки вопросов после публикации попадают в следующую публикацию.
- Переименование опубликованной формы сохраняет старую публичную ссылку через алиасы слага
  (`form_slug_aliases`, не более 10 на форму).
- Удаление формы мягкое и разрешено только без отправок; формы с отправками архивируют.

## Создание и редактирование

- `POST /workspaces/{id}/forms` создаёт форму сразу с `questions[]` и `task_config` в одной транзакции.
  В `task_config` вопросы указываются по `question_index` (позиция в `questions[]`).
- `GET /form-templates` отдаёт локализованные заготовки форм.
- Новый вопрос добавляется в конец или вставляется со сдвигом под блокировкой строки формы.
- `PUT .../questions/reorder` принимает все вопросы формы и проверяет, что правила `visible_if` остаются
  корректными (без циклов).
- `DELETE` формы с отправками отклоняется (`ErrFormHasSubmissions`): такую форму архивируют.
- Вопрос, на который уже есть ответы, сохраняет тип и использованные варианты.

### Типы вопросов

`short_text`, `long_text`, `number`, `email`, `phone`, `url`, `date`, `datetime`, `single_choice`,
`multiple_choice`, `dropdown`, `checkbox`, `rating`, `scale`, `file`, а также оформительские `section`,
`description`, `divider` (ответ на них отклоняется с `NOT_ALLOWED`). Формат ответа каждого типа описан в `openapi.yaml`.

### Условные вопросы

`settings.visible_if` у вопроса: одно правило `{question_id, operator, value}` с операторами `equals`,
`not_equals`, `contains`, `any`. Вопрос показывается, пока правило истинно по ответам. Циклы запрещены
(`FORM_QUESTION_VISIBILITY_CYCLE`), вопрос, на который ссылается правило, нельзя удалить
(`FORM_QUESTION_REFERENCED`). Для невидимого вопроса обязательность не проверяется, а присланный ответ не сохраняется.

## Настройки формы (`settings`)

| Поле | Смысл |
|---|---|
| `submit_button_text` | Текст кнопки (до 80 символов) |
| `success_message` | Сообщение после отправки (до 2000 символов) |
| `redirect_url` | Переход после отправки, только https (в development допускается http) |
| `accent_color` | Цвет в формате `#RRGGBB` |
| `logo_file_id`, `cover_file_id` | Картинки, загруженные как изображения рабочего пространства |
| `notify_on_submit` | До 50 участников, получающих уведомление `form_submission` |
| `closes_at` | Время закрытия приёма |
| `max_submissions` | Максимум отправок (до 1 000 000) |

Публичный ответ отдаёт только публичную часть настроек и абсолютные URL картинок (`PUBLIC_BASE_URL`).

## Публичная отправка

`POST /public/forms/{slug}/submissions`:

- Идемпотентна по заголовку `Idempotency-Key`: повтор с тем же ключом и телом возвращает тот же результат, с другим
  телом отвечает конфликтом.
- Лимит: по IP и на форму (`FORM_SUBMISSIONS_PER_HOUR`, по умолчанию 200 в час), тело до 128 КиБ.
- Ошибки валидации приходят одним ответом 400 с записью в `details` на каждый `answers.<question_id>`.
- Ответ минимальный: без рабочего пространства, версии и данных отвечающего.
- Закрытая (`closes_at`, `ErrFormClosed`), заполненная (`max_submissions`, `ErrFormFull`) и неопубликованная формы отвечают ошибкой.

### Загрузка файлов

`POST /public/forms/{slug}/uploads` для вопросов типа `file`: `multipart/form-data`, тип определяется по
содержимому, размер до `FORM_UPLOAD_MAX_BYTES` (10 МиБ), 30 запросов в минуту. Файл ждёт свою отправку
`FORM_UPLOAD_TTL` (24 часа), после чего фоновая очистка (раз в 10 минут) удаляет его. Приложенные к отправке файлы
становятся вложениями задачи или остаются доступны из отправки.

## Создание задачи из отправки

Настраивается `PUT .../forms/{id}/task-config`. Приоритет источников значения:

```
mappings  >  template  >  task_defaults
```

- `task_defaults`: приоритет, статус, исполнитель, владелец (`owner_id`).
- `template_id`: задача создаётся по шаблону.
- `mappings[]`: ответ на вопрос записывается в цель.

| Цель (`target.type`) | Поле | Примечание |
|---|---|---|
| `task_field` | `title`, `description`, `priority`, `status_id`, `assignee_id`, `assignee`, `due_date` | `assignee` сопоставляет вариант выбора с участником через `transform` |
| `custom_field` | `field_id` | вопрос должен быть совместим по типу |
| `requester` | `name`, `email` | данные заявителя, видны только с правом `task.update` |

Все этапы выполняются в одной транзакции, активность и уведомления записываются после коммита. Если создание задачи
не удалось, отправка сохраняется со статусом `failed`, и её можно повторить:
`POST /submissions/{submission_id}/retry-task-creation`. Статусы создания задачи:
`pending`, `processing`, `succeeded`, `failed`, `skipped`.

### Кто автор задачи

Задача из формы создана **формой** (`created_by` и актор события `form`), владельцем остаётся создатель формы
или `owner_id` из конфигурации, он всегда получает уведомления. Вошедший отвечающий или значения `requester.*`
записываются как заявитель. Общая модель акторов: `user`, `form`, `automation`, `integration`, `system`
(`internal/domain/actor.go`).

## Шаблоны задач

`/workspaces/{id}/task-templates` и `/task-templates/{id}`: версионируемая конфигурация задачи (заголовок, описание, приоритет, теги, поля,
срок). Срок задаётся абсолютной датой `due_date` или относительным `due_in_days`. Шаблон применяется отдельным
запросом или формой. Обновление частичное: непереданные поля не меняются.

## Пользовательские поля

`/workspaces/{id}/custom-fields`: типы и варианты выбора, обязательность (`required`).

- Обязательные поля проверяются при создании задачи (поле `custom_fields` в теле, применение шаблона, задача из
  формы) и не очищаются; ошибка называет поле: `custom_fields.<id>` / `REQUIRED`.
- Изменение поля, у которого есть значения, отклоняется, если сделает их недействительными.
- Название до 255 символов (считаются символы, а не байты).

## Известные ограничения

- Опубликованная версия формы неизменяема: чтобы изменить вопросы, опубликуйте новую версию.
- Повтор создания задачи ручной (`retry-task-creation`), автоматического перезапуска нет.
