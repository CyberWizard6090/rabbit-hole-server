# Долгий ящик

Отложенные задачи и решения. Здесь нет сроков: пункт попадает в работу, когда сработал его триггер или когда о нём
напомнили. Готовое вычёркивайте и переносите в историю PR.

## Отложено по просьбе

| Задача | Зачем | Триггер, когда браться |
|---|---|---|
| Квоты на рабочее пространство: число задач, участников, файлов и размер хранилища | защита от злоупотреблений, предсказуемая стоимость | сервис становится публичным или появляются тарифы |
| Ограничение числа кандидатов поиска для очень частых слов | слово, которое есть в 12 % задач, считается 1–5 секунд под нагрузкой (после #95) | жалобы на медленный поиск по общим словам; решение продуктовое: точные итоги и глобальный порядок против скорости |

## Производительность

| Задача | Подробности | Триггер |
|---|---|---|
| Фильтр по исполнителю в огромных списках | у пользователя без задач в списке из сотен тысяч задач запрос обходит весь список: 120–430 мс одиночно, около 2 с при 16 параллельных запросах ([`performance.md`](performance.md)) | списки больше 100 000 задач или жалобы |
| Индексы остальных внешних ключей на пользователей | авторы комментариев и активности, создатели форм и шаблонов, `resolved_by`, `respondent_id`, `owner_id`, журнал пространства: нужны только для удаления аккаунта, на больших таблицах оно читает их целиком | удаление аккаунтов становится частой операцией или таблицы вырастают до миллионов строк |
| Список задач: счётчики чек-листа | самый тяжёлый обычный запрос, `LEFT JOIN LATERAL`; запаса хватает, но на 32 пользователях он чаще всего дольше 100 мс | рост списков, повторный прогон нагрузки |
| Нагрузочный прогон на отдельной машине | сейчас генератор, сервер и PostgreSQL делят 4 ядра; нужны абсолютные цифры и настройка `shared_buffers`, `work_mem` | перед релизом или при выборе размера сервера |
| Индексы под сортировки списков | покрыты по `created_at`, `priority`, `due_date`, `position`; другие сортировки не проверялись | появятся новые поля сортировки |

## Надёжность и данные

| Задача | Подробности | Триггер |
|---|---|---|
| Политика хранения пользовательских данных | история задач, журнал изменений пространства и мягко удалённые объекты хранятся вечно; чистка из #90 трогает только технические данные | продуктовое решение: восстановление, GDPR, аудит |
| Запись удаления пространства в журнал | журнал уходит вместе с пространством (`ON DELETE CASCADE`) | нужен аудит удалений |
| Повторная отправка мёртвых событий outbox | сейчас вручную SQL-ом по [`operations.md`](operations.md) | события умирают регулярно: добавить команду или эндпоинт |
| Идемпотентность доставки webhook | доставка «минимум один раз», у каждой попытки своя метка `X-Rabbit-Hole-Delivery` | жалобы получателей на дубликаты: общий идентификатор события на все попытки |
| Реальное время по надёжному каналу | события WebSocket best effort, при обрыве клиент перечитывает список | нужны гарантии доставки в реальном времени |
| Семафор argon2 на процесс | защищает память процесса, а не общий бюджет | много реплик с малой памятью |

## Продукт и каналы

| Задача | Подробности |
|---|---|
| Telegram и push-уведомления | каналы уведомлений зарегистрированы через реестр (`ChannelRegistry`), нужны реализация канала и подтверждение адреса |
| Собственные шаблоны досок пространства | сейчас фиксированный каталог (`GET /list-templates`) |
| Файл-контракт для фронтенда | один документ со всеми изменениями API за последние PR (формы, приватность контактов, конверт ошибок, акторы, лимиты, права, журнал, шаблоны, `Accept-Language`): не писался |

## Тесты и качество

| Задача | Подробности |
|---|---|
| Модульные тесты хендлеров | основная проверка идёт через интеграционные тесты |
| `PATCH /lists/{id}`: потерянное обновление | при параллельных правках одного списка снимок строки целиком может затереть чужое поле |

## Проверка в реальной среде

- Настоящий SMTP (подтверждение, сброс пароля, уведомления) и MinIO: проверялось на заглушках и локальных контейнерах.
- WebSocket за nginx и TLS: заголовки `Upgrade` и `Connection`, время жизни билета.
- Фронтенд-страницы `/verify-email`, `/reset-password`, `/confirm-email-change`, `/confirm-channel` (на стороне фронтенда).
