# Роли, права и сессии

## Роли

У каждого рабочего пространства свой набор ролей, который создаётся вместе с ним (`domain.DefaultRoles`).
Назначаемые роли: Admin, Member, Guest. Owner один, им становится создатель.

| Код права | Owner | Admin | Member | Guest |
|---|:-:|:-:|:-:|:-:|
| `workspace.read` | да | да | да | да |
| `workspace.update` (имя, аватар) | да | нет | нет | нет |
| `workspace.delete` | да | нет | нет | нет |
| `member.manage` (участники, Member и Guest) | да | да | нет | нет |
| `member.manage_admins` (выдать Admin, понизить, удалить) | да | нет | нет | нет |
| `space.read` | да | да | да | да |
| `space.create` / `space.update` / `space.delete` | да | да | нет | нет |
| `task.read` | да | да | да | да |
| `task.create` / `task.update` / `task.delete` | да | да | да | нет |
| `form.read` | да | да | да | нет |
| `form.manage` | да | да | нет | нет |
| `template.read` | да | да | да | нет |
| `template.manage` | да | да | нет | нет |
| `customfield.manage` | да | да | нет | нет |

Особенности:

- Гость только читает структуру работы и не видит формы, отправки и шаблоны.
- Владельца нельзя переназначить, удалить или заставить выйти.
- Admin даёт и забирает только Owner (`ADMIN_ROLE_OWNER_ONLY`).
- Добавить в пространство можно только принятый контакт.
- Права проверяет middleware на маршруте: `inWorkspace(domain.PermFormManage)` в `internal/app/router.go`.
  Для задач, списков и пространств рабочее пространство определяется по идентификатору ресурса.
- Для уже существующих пространств строки ролей и прав не обновляются автоматически: после смены набора прав
  нужна миграция данных.

## Анти-перебор идентификаторов

Отсутствующий, удалённый и чужой идентификатор дают один и тот же `403 FORBIDDEN`. Так нельзя проверить,
существует ли ресурс. 404 возвращается только когда нет вложенного объекта внутри доступного контейнера.

## Контакты и приватность

- Контакты основаны на согласии: `POST /contacts` отправляет запрос, который выглядит одинаково для любого id,
  второй пользователь принимает или отклоняет его в `/contacts/requests`.
- Другие пользователи видны только как id, username, имя и аватар. E-mail, bio и часовой пояс не отдаются,
  `/users/search` не ищет по e-mail. Тип ответа с e-mail ломает архитектурный тест.

## Токены

- `POST /auth/login` возвращает `access_token` (`JWT_ACCESS_TTL`, по умолчанию 1 ч) и ставит HttpOnly cookie
  `refresh_token` (путь `/api/v1/auth`, `JWT_REFRESH_TTL`, по умолчанию 168 ч).
- `POST /auth/refresh` вращает refresh-токен. Токены каждого входа образуют семейство (`family_id`). Повтор уже
  использованного токена после 10 секунд допуска (параллельные вкладки) отзывает всё семейство, но не другие
  входы пользователя.
- `POST /auth/logout` требует только cookie. `POST /auth/logout-all`, смена пароля, сброс пароля, смена e-mail и
  `DELETE /profile` поднимают версию токена пользователя и отзывают все выданные ранее токены.
- Access-токен живёт до конца своего срока, но проверяется по версии токена пользователя.
- Фронтенд трактует 401 как «войти заново».

## Защита входа

- Лимиты по IP: регистрация 5 в минуту, вход 10, refresh 30, logout 30, verify-email 20, resend-verification и
  forgot-password 5, reset-password 10 (ответ 429).
- После `AUTH_LOGIN_FAILURE_LIMIT` неудачных входов для одного адреса попытки блокируются с обычным ответом
  «неверные данные», пауза удваивается до `AUTH_LOGIN_LOCK_MAX`. Неизвестные адреса считаются так же.
- Хеширование пароля (argon2id, 64 МиБ) ограничено `AUTH_HASH_CONCURRENCY` одновременными хешами. Лишние запросы
  получают 503 с `Retry-After`.
- `REQUIRE_VERIFIED_EMAIL=true`: до подтверждения адреса вход отвечает 403 `EMAIL_NOT_VERIFIED`.
- Лимиты и блокировка считаются на процесс. IPv6-клиенты группируются по /64.
- `TRUSTED_PROXIES` пуст: заголовок `X-Forwarded-For` игнорируется. За обратным прокси укажите его адреса, но не
  `0.0.0.0/0`.

## Realtime и права

Подписка на события списка, пространства и уведомлений использует одноразовый билет на 30 секунд с правом
`task.read` (см. [`realtime.md`](realtime.md)). При выходе везде, смене или сбросе пароля, удалении аккаунта и
удалении из рабочего пространства сервер сразу закрывает WebSocket пользователя; открытые соединения
перепроверяются каждые две минуты.
